## 1. Executive Summary

This test plan closes **71 identified test gaps** across the AssetVault project — a Spring Boot REST API managing company asset lifecycles. The existing test suite (~99 `@Test` methods) provides solid service-layer coverage but is critically deficient in:

- **Controller-layer HTTP contract tests**: 4 of 6 controllers lack any `@WebMvcTest` coverage
- **End-to-End integration**: Zero `@SpringBootTest` tests spanning the full request→DB→response path
- **Boundary/edge equivalence classes**: Pagination, date boundaries, empty-state scenarios untested at the HTTP layer

After implementing all 71 new test cases (52 from Phase 2 + 19 gap-closing from Phase 3), the project will achieve:
- Full equivalence-class coverage for all 75 functional requirements
- Full controller HTTP-contract testing for every endpoint
- 12 E2E scenarios proving the most critical user workflows against a real H2 database
- ~170+ total test methods, targeting ≥80% line coverage on controller + service layers

## 2. Scope & Out-of-Scope

**In Scope:**
- Unit tests: Controller (`@WebMvcTest`), Service (`@ExtendWith(MockitoExtension)`)
- Integration tests: Repository (`@DataJpaTest`)
- End-to-End tests: `@SpringBootTest` with TestRestClient/MockMvc against embedded H2
- Exception-handling contract verification
- Bean validation wiring tests
- Pagination/sorting behavior
- Auto-generated code sequence verification

**Out of Scope:**
- Performance / load testing
- Security / penetration testing (OWASP)
- Browser / UI compatibility testing
- Third-party SaaS internals
- Concurrency / multi-threaded behavior
- Production database (MySQL/PostgreSQL) specific tests

## 3. Test Strategy by Level

### Unit — Controller (`@WebMvcTest`)
- **Purpose**: Verify HTTP status codes, response shapes, validation wiring, exception mapping
- **Framework**: JUnit 5 + MockMvc + `@MockitoBean`
- **Target coverage**: Every endpoint with ≥1 happy-path + ≥1 error/boundary case
- **Runs on**: Every commit (pre-push)

### Unit — Service (`@ExtendWith(MockitoExtension)`)
- **Purpose**: Verify business logic, state transitions, exception throwing
- **Framework**: JUnit 5 + Mockito + AssertJ
- **Target coverage**: 80%+ line coverage on service layer
- **Runs on**: Every commit

### Integration — Repository (`@DataJpaTest`)
- **Purpose**: Verify custom JPQL/derived queries, boundary behavior with real H2
- **Framework**: JUnit 5 + `@DataJpaTest` + TestEntityManager
- **Target coverage**: All custom query methods
- **Runs on**: Every commit

### End-to-End (`@SpringBootTest`)
- **Purpose**: Verify full flows from HTTP → Controller → Service → Repository → H2 → Response
- **Framework**: JUnit 5 + `@SpringBootTest(webEnvironment = RANDOM_PORT)` + MockMvc or TestRestClient
- **Target coverage**: Critical user journeys (lifecycle flows, seat accounting, code generation)
- **Runs on**: PR gate

### Contract (embedded in Controller tests)
- **Purpose**: Verify error response shape matches NFR-11 (`timestamp/status/error/message/path`)
- **Runs on**: Every commit (part of controller tests)

## 9. Test Data Strategy

### Approach
- **Unit tests (Controller/Service)**: In-line builder methods per test class (already established pattern — `asset()`, `employee()`, `license()`, `request()` helpers)
- **Repository tests**: Use `TestEntityManager.persist()` to seed entities within the transaction
- **E2E tests**: Use REST API calls (POST endpoints) to seed data in a black-box manner — no direct DB manipulation

### Naming Convention
- Test data builders suffixed with scenario: `asset(AssetStatus.RETIRED)`, `employee(true)`, `license(2, LocalDate.now().plusDays(30))`

### Sensitive Data
- No real personal data in tests
- Use synthetic emails: `aarav@example.com`, `test@assetvault.dev`
